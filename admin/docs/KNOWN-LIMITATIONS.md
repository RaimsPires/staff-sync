# Known limitations

Tracked so they can be solved later. Tick an item when it is fixed.

## Open
- [ ] **Report numbers are generated:** `features/reports/model.ts` derives every figure from a hash of the report type, row and dates (so they are stable but not real). Saved reports and email schedules live in `store/reports.ts`; nothing is ever emailed. Exports (CSV, Excel, PDF) do work on the generated rows.
- [ ] **Static key check blind spots:** `yarn keys:check` cannot see keys built from variables or conditions with parentheses; verify those in the browser in both languages.
- [ ] **Audit log content is English-only mock data:** targets, reasons and before/after values in `data/audit.ts` are free text (as a backend would return user-entered text). Action names, target types and UI are translated. The log is static: edits made elsewhere in the dashboard do not add entries.
- [ ] **Profile & security are simulated:** profile edits, password change, 2FA (any 6-digit code is accepted, backup codes are random) and sessions live in `store/profile.ts` only. The profile timezone and phone are not used elsewhere; only the language change is applied (via the locale cookie).
- [ ] **Some Settings are still not applied:** the company name, leave types, grace period and early-leave tolerance (attendance statuses, including the Overview late count), missing check-out handling and auto check-out time, time format, week start, date format, new-site defaults and the one/two-level approval trail follow `store/settings.ts`. Still informational: timezone (no real timestamps yet), overtime rule and approval, mock-location blocking, max sync delay, branch holiday calendars and the payroll export format (there is no payroll export yet). The Overview late count only moves for sites that have sample attendance records, since other sites only have headcount figures.
- [ ] **Settings integrations are simulated:** API keys, webhooks, SSO test, payment card, plan changes, invoices and the data export / company deletion only update local state and show toasts.
- [ ] **Custom roles only apply as a preview:** "Preview" on a role card swaps the signed-in demo user's permissions (sidebar, pages, buttons) for that role's, but the data scope is unchanged and no user can actually sign in as a custom role. Real enforcement needs the backend to resolve a user's role.
- [x] **Role editor URL:** `/users/roles/new` and `/users/roles/[id]` (`?mode=duplicate`); back returns to `/users?tab=roles`. Edits live in the in-memory store, so they still reset on a full refresh (see Mock data).
- [ ] **Invites are not sent:** inviting, resending and revoking only update the in-memory list and show a toast.
- [x] **Employee profile state:** schedules, leave adjustments, device reset, documents, notes and activity now live in `src/store/employee-workspace.ts` and survive leaving the page (not a full refresh).
- [ ] **Address search:** uses the public OpenStreetMap Nominatim service, which is rate-limited. Needs a proper geocoding provider or proxy for production.
- [ ] **French job titles:** a single form is used, with no gender agreement.
- [ ] **Mock data:** all data is in memory (`src/data`, zustand stores) and resets on refresh. Needs the real API behind `services/` and `lib/api.ts`.
- [ ] **Leave balances:** the "used" figures are derived from a hash of the employee name, not real data. Adjustments last for the session only.
- [ ] **Browser coverage is partial:** every page loads without console errors in EN and FR in headless Chrome, and the main flows of Users & Roles, Settings, Reports, Profile, Audit and Leave were clicked through. Dashboard, Live, Attendance, Alerts, Employees, Sites and Schedules interactions were only partly exercised, and nothing was checked visually (layout, dark mode, tablet width).
- [ ] **Route guard is a demo marker:** `src/proxy.ts` redirects signed-out visitors using a plain `ss_auth` cookie set on sign-in. Replace it with a verified, httpOnly session token when there is a backend.
- [ ] **Motion coverage:** modals, drawers, dropdown menus, the sidebar backdrop and page changes animate in and out (`lib/use-presence.ts`, `.ss-*` classes in `globals.css`, reduced-motion respected). The global search panel and toasts only animate in. A new conditionally rendered modal needs `<KeepMounted show={…}>` around it to animate out.
- [ ] **Legacy `nextjs/` folder:** still present; remove once the migration is accepted.

## Fixed
- [x] **Plans:** plan details (prices, limits, feature matrix, subscription, 30-day trial length) live in `store/plans.ts` with seeds in `data/plans.ts`, ready to be loaded from the backend (`load`). Onboarding step 8 still lets a new company pick a plan, which starts a 30-day free trial on it (`startTrial`). Changing plan afterwards happens at `/settings/plans` (sidebar plan card and Settings → Billing link there, never back to onboarding). Still simulated: no payment, no proration, "Contact sales" only shows a toast, the demo employee count (84) is not reset when a trial starts, and a trial-ended workspace link also goes to `/settings/plans`, which needs a real "choose a plan before opening" flow with the backend.
- [x] **Sites vs. the rest of the app:** sites and branches now live in one store (`store/sites.ts`) and every screen reads them through `useOrg()` (`lib/org.ts`), so a new or deactivated site appears in or leaves the scope switcher, dashboard, attendance filters, schedules, reports and role scopes. Sites with no sample attendance (e.g. Lille Annex) have no records, only headcount figures.
- [x] **Leave types:** types are defined once in Settings and used by the Leave inbox, calendar, balances, drawer, notifications and the employee form and profile (`features/leave/use-leave-types.ts`).
