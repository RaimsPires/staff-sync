# StaffSync backend

FastAPI modular monolith (PostgreSQL 16 + PostGIS, Redis, ARQ worker) serving the admin dashboard and the mobile app
under `/api/v1`. Design: `../Backend API.md`.

## Run locally

Shortcut: `make dev` (or `./scripts/dev.sh`) does everything below, then serves on http://localhost:8000/api/v1/docs.

```bash
docker compose up -d                  # PostGIS on :5433, Redis on :6380 (ports avoid other local containers)
cp .env.example .env
uv sync
uv run alembic upgrade head           # runs as the owner role; the API connects as the least-privilege role (RLS applies)
uv run uvicorn staffsync.main:app --reload     # http://localhost:8000/api/v1/docs
uv run arq staffsync.workers.settings.WorkerSettings   # outbox relay, absences, reminders, retention
```

In dev, e-mail/SMS codes are written to the server log (`notify` lines) instead of being sent.

Demo data: `make seed` loads "Demo Logistics" (owner `admin@admin.com` / `admin12345`, two sites, five employees who all use the password `admin12345` with their phone number; the numbers are printed). Change the constants at the top of `scripts/seed_dev.py` to use others (passwords need 10+ characters). It stops if the demo owner already exists; `make reset` wipes the database first. `make worker` runs the background worker, which the live board needs (events reach the browser through the outbox relay).

Whole stack in one command: `../scripts/dev.sh` (add `--seed` once, `--lan` for a phone).

## Configuration and providers

Everything that needs a credential is a setting in `.env` (see `.env.example`, which documents each one): SMTP for e-mail, Twilio or Africa's Talking for SMS, Expo for push, S3 for files, Google and Microsoft for dashboard sign-in, Play Integrity, Stripe. Leave a group empty and that feature keeps its development behaviour (codes and links in the server log, files on local disk, sign-in buttons say "not set up").

## Production notes

- `CORS_ORIGINS` (JSON list) must contain the dashboard's origin.
- The refresh cookie is `SameSite=Strict`, so the dashboard and the API must be on the same site (for example `app.example.com` and `api.example.com`); different registrable domains would need `SameSite=None`.
- Set `APP_ENV=prod`, real `JWT_SECRET`, `SERVER_PEPPER`, `FIELD_ENCRYPTION_KEY`, an S3 bucket, and the e-mail, SMS and push providers; the dev adapters only print to the console and do not store uploads.

## Tests

```bash
uv run pytest        # needs `docker compose up -d`; creates a throwaway `staffsync_test` database
uv run ruff check src tests
```

## Layout

`src/staffsync/` — `core/` (config, db, security, deps, errors, audit, outbox), `common/` (base repository, geo, pagination),
`modules/<name>/` (router → service → repository/models), `workers/`, `migrations/`.
Migrations: `0000` extensions, `0001` schema (autogenerated), `0002` Row-Level Security + grants.
While the schema is still moving, `scripts/regen_migrations.py` rebuilds the chain.

## What is real and what is a stub

Real and tested: auth (password+TOTP, mobile OTP, refresh rotation with reuse detection), companies/branches/sites with PostGIS
geofences, employees/devices/CSV import, roles & scopes, schedules and shift expansion, the check-in pipeline (offline sync,
proxy, PIN lockout), alerts/corrections, leave, audit, dashboard, reports (CSV/XLSX), webhooks, Stripe webhook handling, soft delete/trash.

Built but needs credentials to act for real: e-mail, SMS, push, S3, Google/Microsoft sign-in, Play Integrity, Stripe checkout and
portal. Not built: iOS App Attest verification.

## Passwords for new people

Creating an employee (Employees > Add, with "Send sign-in details" on) or inviting a dashboard user generates a random temporary password and mails it (employees without an e-mail get it by SMS). The person must choose their own password at first sign-in. People are matched by e-mail first, then phone; an existing account keeps its password. Dashboard users' temporary passwords expire with their 7-day invitation. Without SMTP/Twilio keys the message only appears in the server log.
